# Fase 3.5 — Plan 6: Legacy Angular 14 frontend + partial cutover — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Serve the real vendored Angular 14 app (`serfel-ang`) from the rehost front door, repointed to the same-origin rehosted backends, so it loads and its **rehosted** features work (login via SerfelWeb, sales, orders, Distribuidor/SerfelWeb). **Partial cutover** (decided): the `products`/`routes` services were not rehosted, so those pages will error — accepted.

**Architecture:** Builds on the deployed Fase 3.5 (branch `feat/phase3.5-rehost-foundation`). The `RehostLegacyFrontend` StaticSite is repointed from the `legacy-frontend-skeleton` placeholder to the real Angular 14 build. Environment base URLs become **same-origin paths** so the browser calls `/SerfelWeb/*`, `/sales/*`, `/orders/*` etc. through the same CloudFront distribution (no CORS). The Basic Auth interceptor keys off `environment.apiUrl`; setting it to `''` makes it attach Basic Auth to every logged-in same-origin API call (covers the node Lambdas).

**Tech Stack:** Angular 14 (built with **Node 16**, not 22), SST v3 StaticSite (S3 + CloudFront), AWS.

## Global Constraints

- Region us-east-1; `AWS_PROFILE=admin-christian`; branch `feat/phase3.5-rehost-foundation` (commit here, do NOT branch).
- **Angular 14 build requires Node 16** — use `~/.nvm/versions/node/v16.20.2/bin` on PATH for `npm ci`/`ng build`. SST itself runs on Node 22 (`~/.nvm/versions/node/v22.23.1`), so build the app SEPARATELY with Node 16 and point the StaticSite at the pre-built `dist/` (no SST-run build command).
- Deploys SYNCHRONOUS + FOREGROUND (Bash `timeout` 600000); poll CloudFront to `Deployed`. `git checkout` any regenerated `apps/frontend/src/environments/environment.gen.ts` (the NEW Angular frontend, unrelated).

- `apps/legacy-frontend` is OUT of the pnpm workspace (Task 2a) — it has its own `node_modules` from `npm ci`.

## Task 1: Repoint environment + build the Angular 14 app (Node 16)

**Files:** modify `apps/legacy-frontend/src/environments/environment.ts` and `environment.prod.ts`.

- [ ] **Step 1: Repoint both environment files to same-origin rehost paths.** `ng build` defaults to the production configuration in Angular 14 (which file-replaces `environment.ts` → `environment.prod.ts`), so set BOTH to identical same-origin values to be safe.

`environment.ts`:
```typescript
export const environment = {
  production: false,
  esCoproad: true,
  apiUrl: '',                              // interceptor prefix: '' => auth all logged-in same-origin API calls
  apiUrlSerfelWeb: '/SerfelWeb',           // login (LoginREST/login2) + precio service — rehosted
  apiProductos: '/products',               // NOT rehosted (partial cutover) — product pages will error
  apiPorciones: '/products/portions',      // NOT rehosted
  apiRutas: '/routes',                     // NOT rehosted
  apiPDF: '/pdf',                          // NOT rehosted
  apiPedidos: '/orders',                   // orders Lambda — rehosted
  apiVentas: '/sales',                     // sales Lambda — rehosted
};
```
`environment.prod.ts`: same object but `production: true` (keep `esCoproad: true`).

- [ ] **Step 2: Build with Node 16.**
```bash
export PATH="$HOME/.nvm/versions/node/v16.20.2/bin:$PATH"
cd serfel/apps/legacy-frontend
node --version   # expect v16.20.2
npm ci
npx ng build   # Angular 14 default = production config; outputs dist/serfel-ang
```
Expected: build succeeds → `dist/serfel-ang/index.html` + JS/CSS bundles. (If `npm ci` fails on peer deps, use `npm ci --legacy-peer-deps`. If the budget `maximumError 5mb` trips the build, raise it in `angular.json` — it's a hard error only if exceeded.)

- [ ] **Step 3: Sanity-check the build output** references same-origin paths (no `localhost`):
```bash
grep -roE "localhost:[0-9]+|http://localhost" dist/serfel-ang/*.js | head || echo "no localhost refs ✓"
ls dist/serfel-ang/index.html && echo "build OK"
```
Expected: `build OK`; no `localhost` references remain (they were compiled from environment).

- [ ] **Step 4: Commit** (source env changes; the `dist/` is a build artifact — gitignore it):
```bash
cd serfel
echo 'apps/legacy-frontend/dist/' >> .gitignore
git add apps/legacy-frontend/src/environments/environment.ts apps/legacy-frontend/src/environments/environment.prod.ts .gitignore
git commit -m "feat(rehost): repoint legacy Angular 14 to same-origin rehost paths"
```

## Task 2: Point the StaticSite at the real build + deploy + verify

  path: "apps/legacy-frontend/dist/serfel-ang",

export const legacyFrontendUrl = legacySite.url;

- [ ] **Step 4: Verify it serves** through the rehost CDN:
```bash
CDN=$(AWS_PROFILE=admin-christian aws cloudfront list-distributions --region us-east-1 \
  --query "DistributionList.Items[?Comment=='serfel-dev-rehost-router'].DomainName | [0]" --output text)

```
Expected: `/` → 200; the index references the Angular bundles (`main.*.js` etc.), not the skeleton placeholder text; no `localhost`.
