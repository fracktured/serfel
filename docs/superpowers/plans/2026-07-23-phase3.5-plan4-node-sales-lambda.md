# Fase 3.5 — Plan 4: node-app-1 (sales API) → Lambda (Express wrapped) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Run the existing `api-ventas-node` Express+Sequelize app **as-is** in a Lambda (via `@codegenie/serverless-express`), connected to the `serfel` RDS DB, reachable through the rehost front door at `/sales/*`, keeping the app's own Basic-Auth-against-DB. No rewrite.

**Architecture:** Builds on the deployed Fase 3.5 foundation + Plan 2 (branch `feat/phase3.5-rehost-foundation`). The app authenticates itself, so the API Gateway route has **no** authorizer.

**Tech Stack:** SST v3, AWS Lambda (Node 22, ARM64), API Gateway HTTP API, CloudFront, Express, Sequelize (mysql2), `@codegenie/serverless-express`, RDS MariaDB.

- [ ] **Step 4: Write the Lambda handler** — Create `lambdas/node-app-1/index.ts`. It fetches the DB secret ONCE, sets `process.env.DB_*` BEFORE the app module (and its module-level Sequelize) loads via dynamic import, then wraps the Express app:

```typescript
import serverlessExpress from "@codegenie/serverless-express";
import {
  GetSecretValueCommand,
  SecretsManagerClient,
} from "@aws-sdk/client-secrets-manager";

const sm = new SecretsManagerClient({});
let cached: ReturnType<typeof serverlessExpress> | undefined;

async function bootstrap() {
  const secret = await sm.send(
    new GetSecretValueCommand({ SecretId: process.env.DB_SECRET_ARN })
  );
  const c = JSON.parse(secret.SecretString!) as {
    host: string; username: string; password: string; dbname: string;
  };
  // Sequelize (src/config/bd.sequelize.ts) reads these at import time.
  process.env.DB_HOST = c.host;
  process.env.DB_USER = c.username;
  process.env.DB_PWD = c.password;   // note: DB_PWD, not DB_PASS
  process.env.DB_NAME = c.dbname;    // = "serfel"
  const app = (await import("./src/app")).default;
  return serverlessExpress({ app });
}

export const handler = async (event: unknown, context: unknown) => {
  cached ??= await bootstrap();
  return (cached as (e: unknown, c: unknown) => unknown)(event, context);
};
```

## Task 2: Deploy the sales Lambda + route it through the front door

**Files:** modify `infra/rehost/node-api.ts`, `infra/rehost/cdn.ts`.

- [ ] **Step 1: Add the sales Function + route** — In `infra/rehost/node-api.ts`, after the health function, add the sales Lambda and its route (NO authorizer — the app authenticates). Sequelize + its dialect can't be esbuild-bundled (dynamic require), so install them into the bundle:

```typescript
const salesFn = new sst.aws.Function("RehostSalesFn", {
  handler: "lambdas/node-app-1/index.handler",
  runtime: "nodejs22.x",
  architecture: "arm64",
  timeout: "20 seconds",
  memory: "512 MB",
  vpc: { privateSubnets: privateSubnetIds, securityGroups: [sgLambdaId] },
  environment: { DB_SECRET_ARN: dbSecretArn },
  permissions: [{ actions: ["secretsmanager:GetSecretValue"], resources: [dbSecretArn] }],
  nodejs: { install: ["sequelize", "mysql2"] },
  transform: { function: { name: "serfel-dev-rehost-sales" } },
});

// The Express app routes at /sales/ ; no API Gateway authorizer (app does Basic Auth).
for (const method of ["GET", "POST", "PUT", "DELETE"] as const) {
  nodeApi.route(`${method} /sales/{proxy+}`, salesFn.arn);
}
```
