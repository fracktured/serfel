# Fase 5 — AWS WAF over CloudFront Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add one CLOUDFRONT-scope AWS WAF Web ACL (IP reputation + known-bad-inputs + 1000/5min rate limit, Block mode) attached to the project's three public CloudFront distributions.

**Architecture:** A raw Pulumi `aws.wafv2.WebAcl` lives in a new `infra/waf.ts` and exports `webAclArn`. Each of the three CloudFront distributions (`Frontend` StaticSite, `RehostRouter` Router, `RehostLegacyFrontend` StaticSite) attaches the *same* ACL by setting `webAclArn` inside its `transform.cdn` callback — the SST `Cdn` component exposes `webAclArn` as a first-class input that maps to the distribution's `webAclId`. No separate association resource: for CLOUDFRONT scope the association *is* the `webAclId` on the distribution.

**Tech Stack:** SST v3 (Ion/Pulumi), `@pulumi/aws` (`aws.wafv2.WebAcl`), TypeScript. Region `us-east-1` (required for CLOUDFRONT-scope ACLs).

## Global Constraints

- Region is `us-east-1` for the whole stack; CLOUDFRONT-scope Web ACLs must be created there. No region override needed — the provider default already applies.
- Raw Pulumi resources import aws as `import * as aws from "@pulumi/aws";` and carry a `Name` tag `serfel-dev-*` merged with `...stackTags(...)`. Follow this verbatim.
- The Web ACL is shared security infrastructure → tag `serfel:stack=serfel-shared` via `stackTags("serfel-shared")` from `infra/tags.ts`. Do NOT re-add `Project`/`Owner`/`Environment` (those come from `defaultTags` in `sst.config.ts`).
- Managed rule groups use `overrideAction: { none: {} }` (keep the vendor's Block actions). The rate-based rule uses `action: { block: {} }`. These are mutually exclusive per rule — a managed-group rule must NOT set `action`, and the rate rule must NOT set `overrideAction`.
- No Core Rule Set (CRS) — deliberately excluded to avoid `SizeRestrictions_BODY`/XSS-on-JSON false positives on rehost PHP form posts and the node API.
- The new-app Cognito HTTP API stays WAF-less by design (HTTP API v2 can't take WAF; it's not behind CloudFront). Do NOT try to attach WAF to it.
- Infra has no vitest harness. The "test" for each task is `pnpm typecheck` (compiles the infra TS) plus, for the final task, `sst deploy` + AWS CLI/console verification — mirroring the Fase 5 tagging task.
- Commit after every task with a `feat(infra)` / `chore(infra)` message ending with the Co-Authored-By trailer.

### Task 1: WAF module + wire into sst.config.ts

**Files:**
- Create: `infra/waf.ts`
- Modify: `sst.config.ts` (add `await import("./infra/waf");` before the `frontend` and `rehost/cdn` imports)

**Interfaces:**
- Consumes: `stackTags` from `infra/tags.ts` (signature `stackTags(stack: "serfel-aws" | "serfel-rehost" | "serfel-shared"): { "serfel:stack": StackTag }`).
- Produces: `export const webAclArn` — a `pulumi.Output<string>` holding the Web ACL ARN. Tasks 2-4 import `{ webAclArn }` from `./waf` / `../waf`.

- [ ] **Step 1: Create `infra/waf.ts` with the Web ACL**

```ts
import * as aws from "@pulumi/aws";
import { stackTags } from "./tags";

// CLOUDFRONT-scope Web ACL. Must live in us-east-1 (the stack's region).
// Attached to all three public CloudFront distributions via each component's
// `transform.cdn` (webAclArn). HTTP API v2 can't take WAF directly, so the
// new-app Cognito API stays uncovered by design — see the WAF design spec §2.1.
const webAcl = new aws.wafv2.WebAcl("SerfelWaf", {
  name: "serfel-dev-waf",
  scope: "CLOUDFRONT",
  defaultAction: { allow: {} },
  rules: [
    {
      name: "AmazonIpReputationList",
      priority: 0,
      // Managed group: keep the vendor's built-in Block actions.
      overrideAction: { none: {} },
      statement: {
        managedRuleGroupStatement: {
          vendorName: "AWS",
          name: "AWSManagedRulesAmazonIpReputationList",
        },
      },
      visibilityConfig: {
        cloudwatchMetricsEnabled: true,
        metricName: "serfel-ip-reputation",
        sampledRequestsEnabled: true,
      },
    },
    {
      name: "KnownBadInputs",
      priority: 1,
      overrideAction: { none: {} },
      statement: {
        managedRuleGroupStatement: {
          vendorName: "AWS",
          name: "AWSManagedRulesKnownBadInputsRuleSet",
        },
      },
      visibilityConfig: {
        cloudwatchMetricsEnabled: true,
        metricName: "serfel-known-bad-inputs",
        sampledRequestsEnabled: true,
      },
    },
    {
      name: "RateLimit",
      priority: 2,
      // Custom rate rule: this one uses `action`, not `overrideAction`.
      action: { block: {} },
      statement: {
        rateBasedStatement: {
          limit: 1000, // requests per IP per evaluation window
          aggregateKeyType: "IP",
          evaluationWindowSec: 300, // 5-minute sliding window
        },
      },
      visibilityConfig: {
        cloudwatchMetricsEnabled: true,
        metricName: "serfel-rate-limit",
        sampledRequestsEnabled: true,
      },
    },
  ],
  visibilityConfig: {
    cloudwatchMetricsEnabled: true,
    metricName: "serfel-waf",
    sampledRequestsEnabled: true,
  },
  tags: { Name: "serfel-dev-waf", ...stackTags("serfel-shared") },
});

export const webAclArn = webAcl.arn;
```

    await import("./infra/waf");
    await import("./infra/api");

Expected: PASS (no errors). If `aws.wafv2.WebAcl` types complain about a rule setting both `action` and `overrideAction`, re-check that managed groups use only `overrideAction` and the rate rule uses only `action`.

### Task 5: Deploy to dev, verify associations, smoke-test, document

**Files:**
- Modify: `docs/superpowers/specs/2026-08-04-phase5-waf-design.md` (check off §10 checklist items as completed) — optional bookkeeping.
- No code changes; this task deploys and verifies Tasks 1-4.

**Interfaces:**
- Consumes: the deployed stack from Tasks 1-4.
- Produces: a verified live Web ACL with three distribution associations.

- [ ] **Step 1: Deploy to dev**

Run: `pnpm sst:deploy` (or `npx sst deploy --stage dev`)
Expected: succeeds; the plan shows one `aws:wafv2:WebAcl` create and updates to the three CloudFront distributions (setting `webAclId`).

Note: if the DB instance is stopped, that's fine — WAF/CloudFront changes don't need it. CloudFront distribution updates can take several minutes to propagate.

- [ ] **Step 2: Confirm the Web ACL and its rules exist**

Run:
```bash
aws wafv2 list-web-acls --scope CLOUDFRONT --region us-east-1 \
  --query "WebACLs[?Name=='serfel-dev-waf'].{Name:Name,Id:Id,ARN:ARN}"
```
Then, using the returned Id:
```bash
aws wafv2 get-web-acl --scope CLOUDFRONT --region us-east-1 \
  --name serfel-dev-waf --id <ID> \
  --query "WebACL.Rules[].{Name:Name,Priority:Priority}"
```
Expected: three rules — `AmazonIpReputationList` (0), `KnownBadInputs` (1), `RateLimit` (2).

- [ ] **Step 3: Confirm all three distributions are associated**

Run (using the Web ACL ARN from Step 2):
```bash
aws wafv2 list-resources-for-web-acl --web-acl-arn <ARN> \
  --resource-type CLOUDFRONT --region us-east-1
```
Note: `list-resources-for-web-acl` covers REGIONAL resources; for CLOUDFRONT, verify instead via the console (**WAF → Web ACLs → serfel-dev-waf → Associated AWS resources**) OR by reading each distribution's `WebACLId`:
```bash
aws cloudfront list-distributions \
  --query "DistributionList.Items[].{Domain:DomainName,WebACLId:WebACLId}"
```
Expected: the three project distributions (new-app Frontend, rehost Router, rehost legacy frontend) each show a non-empty `WebACLId` equal to the ACL ARN; any unrelated distribution is empty.

- [ ] **Step 4: Smoke — benign request still succeeds**

Run (against the new-app frontend CloudFront domain):
```bash
curl -s -o /dev/null -w "%{http_code}\n" https://<frontend-cloudfront-domain>/
```
Expected: `200`.

- [ ] **Step 5: Smoke — KnownBadInputs probe is blocked**

Run:
```bash
curl -s -o /dev/null -w "%{http_code}\n" \
  -H 'User-Agent: ${jndi:ldap://x/a}' https://<frontend-cloudfront-domain>/
```
Expected: `403` (WAF blocks the Log4j-style pattern via KnownBadInputs). If it returns 200, check the rule deployed with `overrideAction: { none: {} }` (not overridden to Count).

- [ ] **Step 6: (Optional) Smoke — rate limit**

Only if you want to confirm the rate rule live (it will briefly self-block your IP for ~5 min):
```bash
for i in $(seq 1 1100); do \
  curl -s -o /dev/null -w "%{http_code}\n" https://<frontend-cloudfront-domain>/ ; \
done | sort | uniq -c
```
Expected: a run of `200` then `403` once the per-IP count crosses ~1000 in the window. Wait ~5 min for the block to clear.
